# Инструкция для заместителей хакимов районов

> **Аудитория:** заместители хакимов 13 районов Кашкадарьинской области
> по вопросам инвестиций.
> **Цель:** каждый заместитель ежеквартально (и чаще) вносит данные по
> своему району в единую систему, чтобы аппарат заместителя хакима
> области видел полную картину.

## Что такое GitHub и этот репозиторий

GitHub — это система совместной работы с документами. Все данные
хранятся централизованно, каждое изменение подписывается автором и
сохраняется в истории. Вы не можете случайно удалить чужие данные —
система это не даст.

Адрес репозитория: `https://github.com/shuh2398/TV`

## Что вы будете заполнять

В папке `districts/` есть 13 подпапок — по одной на район. В вашей
папке (например, `districts/03-shahrisabz/`) находятся 4 файла:

| Файл | Что вносить | Частота |
|------|-------------|---------|
| `plan.md` | Годовой план: инвестиции, проекты, рабочие места, экспорт | Раз в год, при утверждении |
| `execution.md` | Факт по кварталам, % выполнения, отклонения | Ежеквартально |
| `projects.md` | Список конкретных проектов с характеристиками | По мере изменений |
| `sites.md` | Свободные земельные участки и здания | Ежемесячно |

**Вам разрешено править ТОЛЬКО папку своего района.** Попытка изменить
чужой район будет автоматически заблокирована системой (CODEOWNERS).

## Первичная настройка (один раз)

1. **Регистрация на GitHub.** Перейдите на `https://github.com`,
   создайте аккаунт на рабочую почту. Запомните логин (username) и
   сообщите его в аппарат заместителя хакима области.
2. **Двухфакторная аутентификация.** В настройках включите 2FA
   (SMS или приложение Google Authenticator) — это требование
   информационной безопасности.
3. **Приглашение в репозиторий.** Аппарат области отправит вам
   приглашение на почту — нажмите кнопку **«Accept invitation»**.
4. **Проверка доступа.** Откройте ссылку репозитория, перейдите в
   папку своего района, убедитесь, что видите файлы.

## Как внести изменения (каждый раз)

### Вариант А: через веб-интерфейс GitHub (рекомендуется)

1. Откройте нужный файл, например `districts/03-shahrisabz/execution.md`.
2. Нажмите на иконку карандаша в правом верхнем углу (✏️ **Edit this file**).
3. Внесите правки прямо в браузере — таблицы в формате Markdown,
   символы `|` разделяют колонки.
4. Прокрутите вниз до блока **«Commit changes»**.
5. В первом поле напишите краткое описание: `обновил факт Q1 2026`.
6. Выберите **«Create a new branch and start a pull request»**.
7. Имя ветки оставьте по умолчанию, нажмите **«Propose changes»**.
8. На следующем экране нажмите **«Create pull request»**.
9. Заполните поля шаблона PR (период, источник, подпись).
10. Нажмите **«Create pull request»** ещё раз.
11. Ожидайте одобрения от аппарата области (обычно 1–2 рабочих дня).

### Вариант Б: через мобильное приложение GitHub

То же самое, только с телефона — есть приложение GitHub для iOS и
Android.

## Правила заполнения таблиц

- **Суммы** — в миллионах долларов США (если не указано иное),
  используйте точку, не запятую: `12.5`, не `12,5`.
- **Количества** — целые числа без пробелов: `245`, не `245 чел.`.
- **Даты** — в формате `ГГГГ-ММ-ДД`: `2026-04-14`.
- **Пустые поля** — оставляйте пустыми, не ставьте `0` вместо
  отсутствующих данных.
- Не удаляйте строки и колонки таблиц. Если в таблице не хватает
  строк — скопируйте последнюю и добавьте ниже.

## Что делать при ошибке

- Если вы допустили опечатку в PR, который ещё не одобрен —
  откройте файл, снова нажмите карандаш и внесите правку в **ту же
  ветку** (GitHub предложит вариант).
- Если PR уже одобрен и слит — просто создайте новый PR с
  исправлением.
- Если не получается — напишите в аппарат области на `TODO@email`
  или позвоните `TODO-номер`.

## Что НЕ надо делать

- ❌ Не меняйте структуру таблиц (заголовки, порядок колонок).
- ❌ Не удаляйте чужие данные, даже если они кажутся неверными —
  сообщите в аппарат области.
- ❌ Не публикуйте в репозитории персональные данные физических лиц
  (паспорта, ИНН, адреса проживания).
- ❌ Не передавайте свой пароль от GitHub коллегам.
