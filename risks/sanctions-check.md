# Санкционный чек-лист

Методика обязательной проверки российских контрагентов перед включением
в качестве потенциального партнёра по проекту Кашкадарьинская область ↔
Кировская область. Без прохождения этого чек-листа компания **не** может
быть включена в рекомендации.

> Данный документ — внутренняя операционная памятка, а не юридическое
> заключение. Решения о допуске контрагента принимаются уполномоченными
> лицами хокимията и юридическим советником с опорой на первоисточники.

## 1. Списки, подлежащие сверке

Проверяется каждая российская сторона (юр. лицо, бенефициары, банк,
обслуживающие фин. организации):

1. **US OFAC** — Specially Designated Nationals (SDN) List, Sectoral
   Sanctions Identifications List (SSI), Non-SDN Menu-Based Sanctions
   List (NS-MBS). Официальный поисковик — OFAC Sanctions List Search
   (URL зафиксировать при фактической проверке в `data/sources.md`).
2. **EU** — Consolidated list of persons, groups and entities subject
   to EU financial sanctions (ведётся Советом ЕС).
3. **UK HMT** — UK Sanctions List (Office of Financial Sanctions
   Implementation, HM Treasury).
4. **Иные юрисдикции по необходимости:** Канада, Австралия, Япония,
   Швейцария, Украина — если проект предполагает контрагентов или
   расчёты в этих юрисдикциях.
5. **Риск вторичных санкций** — оценка для контрагентов из РУз,
   работающих с подсанкционными российскими лицами, с учётом
   заявлений Минфина США и позиции регуляторов РУз.

> Актуальные URL поисковиков каждого списка фиксируются как источники
> `S-YYYY-NNN` при проведении первой проверки.

## 2. Что проверяется у российского контрагента

- Само юридическое лицо (название, ИНН, ОГРН, альтернативные
  наименования, предыдущие названия).
- Мажоритарные владельцы / конечные бенефициары (доля ≥ 50 % —
  правило OFAC 50 %, а также кумулятивные доли).
- Руководители.
- Обслуживающие банки (подсанкционный банк → риск для расчётов).
- Материнская структура, если применимо.
- Санкционный статус отрасли (например, секторальные ограничения).

## 3. Процедура

1. Открыть карточку стейкхолдера в `stakeholders/ru/<компания>.md`.
2. По каждому из списков п. 1 — выполнить поиск, зафиксировать:
   - **дату проверки** (`YYYY-MM-DD`),
   - **используемый источник** (запись `S-YYYY-NNN` в `data/sources.md`),
   - **результат**: найдено / не найдено / частичное совпадение требует
     ручного анализа.
3. Зафиксировать результат в разделе «Санкционный статус» карточки
   стейкхолдера.
4. При сомнительном совпадении — в `questions-open.md` открыть вопрос
   на юридическую консультацию.
5. При обнаружении совпадения — компания получает итог «не допустим»,
   и причина фиксируется ссылкой на источник.

## 4. Периодичность переподтверждения

- Перед подписанием любого юридически значимого документа.
- Перед публикацией списка рекомендованных партнёров.
- Иначе — **не реже чем раз в 90 дней** для ранее проверенных контрагентов.

## 5. Чего делать нельзя

- Опираться на «память» или общее впечатление — только актуальная
  сверка по официальному списку.
- Проверять только название без проверки бенефициаров.
- Публиковать в репозитории «чистый» статус без указания даты и
  источника сверки.
- Переносить статус с одной компании группы на другую без отдельной
  проверки.

## 6. Ведение журнала проверок

Журнал фактически проведённых проверок ведётся в карточках стейкхолдеров
и в `data/sources.md`. Отдельного свода журнала здесь не хранится —
первичным источником истины является карточка компании.
